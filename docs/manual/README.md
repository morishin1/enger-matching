# ENGER マニュアル運用の設計（イシュー定義）

> マニュアルは「親切のため」ではなく**売上を上げるための道具**として運用する。
> 本ファイルはその設計図。各マニュアル本体は同じフォルダの 3 ファイル：
> `freelance.md`（フリーランスサイト）／`business.md`（企業サイト）／`agent.md`（エージェント＝DX社内）

## 1. 売上の方程式とマニュアルの役割

```
売上 = 成約数 × マージン
成約数 = 提案数 × 成約率
提案数 = 提案可能な人材の数 × 提案先になる案件の数 × エージェントの処理量
成約率 = マッチング精度 × クロージングの質
```

マニュアルは、この式の**どの変数を動かすための文書か**を明確にして書く・運用する。
「操作説明」は手段であり、ゴールは**読者に売上へ繋がる行動を完走させること**。

## 2. サイト別のイシューとマニュアルの狙い

| サイト | 売上に効く変数 | イシュー（現状の詰まり） | マニュアルの狙い（=ゴール行動） | 追うKPI |
|---|---|---|---|---|
| **フリーランス**（enger.jp） | 提案可能な人材の数 | 登録しただけで止まる。プロフィール未完成・面談未完了だと応募もスカウトも動かず、**登録者が売上に変換されない** | 登録 → プロフィール完成（スキルカード・スキルシート） → 担当面談 → 応募/スカウト即返信 の**完走** | プロフィール完成率／スキルシート提出率／面談完了率／スカウト返信率 |
| **企業**（ENGER business） | 提案先になる案件の数 × 成約率 | 使い方が分からず放置 → 自社情報が空・案件が入らない → **提案先がなく、あっても刺さらない** | 面談 → 自社情報100%（充実度メーター） → 案件掲載 → 会いたい評価 の**完走** | 充実度100%企業率／掲載案件数／会いたい評価数／評価→面談転換率 |
| **エージェント**（DX社内） | 処理量 × マッチング精度 × クロージングの質 | 運用が属人化（失注理由が浅い・企業カルテ未記入） → **データが汚れて学習ループが回らない**、人によって処理量が違う | 操作説明ではなく**売上に繋がる運用ルールの標準化**（1日の流れ・失注の書き方・企業カルテ・AIの使い所） | 提案数/人／失注理由「その他」率／企業カルテ記入率／成約率 |

## 3. 運用ルール（作って終わりにしない）

1. **機能とセットで更新**：機能追加・変更の PR には該当マニュアルの更新を含める（更新責任＝実装者）。
2. **FAQ化ルール**：同じ質問が**2回**来たら、その週のうちに該当マニュアルのFAQへ追記する（出所：チャット・担当への問い合わせ・フィードバックチケット）。
3. **月次レビュー**：上表のKPIを月1で確認し、「数字が動かない章」を書き直す（読まれない/効かないマニュアルは放置しない）。
4. **公開範囲**：フリーランス向け＝公開可（SEO・集客に寄与）。企業向け＝ログイン後。エージェント向け＝**社内限定**（単価・商流・運用ノウハウを含むため外部厳禁）。
5. **表記**：例文に実在の人名・社名を使わない。企業向けには匿名原則（人材＝イニシャル表示）の「理由」を必ず説明する（不信感→離脱の防止）。

## 4. 配信形態

- DX 内：ヘッダー「マニュアル」→ `/manual`（ログイン必須・ロール別出し分け・実装済み）。
- 本フォルダの md は**原稿の正**。イラスト付き版（ChatGPT等で作成）は本文を変えず挿絵のみ追加する。
  各所に `[イラスト案: …]` を置いてあるので、そのままイラスト生成の指示として使える。
